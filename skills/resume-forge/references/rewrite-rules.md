# 中文简历：结构与写作规则

## 一、结构（2 页版默认）

```text
抬头       姓名 + 岗位 + 一句话定位 + 联系方式（4 项以内）
个人概述   4~5 行，回答"你是谁、做过什么量级的事、现在在做什么"
核心能力   5~6 行，每行「能力域 → 具体技术与落地证据」，不写熟练度
核心项目   2~3 个，有深度，每个 4~5 条 bullet + 一句项目描述
工作经历   时间轴，每段 1~2 行，只写职责边界，不重复项目指标
教育背景   1~2 行
```

### 为什么"核心项目"在前

招聘方先判断"这人做过什么量级的事"，再看"在哪家公司"。工作经历若放在前面，会迫使读者用低信息量的职责句去猜项目深度。项目前置后，工作经历退化为诚实的时间轴，两者不再重复。

### 工作经历的三条硬规矩

1. 一段经历最多 1 行职责 + 1 行技术环境；指标全部上移到核心项目。
2. 早期经历合并成一行（`公司 A · 公司 B · 公司 C`），只保留"代表项目 + 量级"。
3. 时间格式统一 `YYYY.MM`，用 tabular-nums 对齐。

## 二、bullet 句型

固定三段式：**动作 + 产物 + 结果**。

```text
[2~4 字标签：] 做法 → 产物 → 服务对象/规模 → 结果
```

合格示例：

- `微前端改造：基于 qiankun/wujie 拆分内部平台，多业务线子应用独立部署、并行迭代，解除单体应用的发布耦合`
- `前端监控平台：搭建错误采集 → 告警 → 定位链路，线上故障平均发现时间 15 分钟 → 3 分钟，处理效率提升 75%`
- `组件库：沉淀 20+ 业务组件，接入 8 条内部业务线，开发效率提升约 25%`

不合格（要改）：

| 写法 | 问题 |
|---|---|
| 负责前端团队管理，推动技术升级 | 只有职责，没有产物和结果 |
| 精通 Vue、React，熟悉 Node.js | 自我声明，无证据 |
| 使用 Vue3 进行了性能优化 | 无动作细节、无产物、无结果 |
| 优化了系统性能，提升用户体验 200 倍 | 数字无口径、无场景 |

## 三、数字规则

1. **有基线才写箭头。** `3.5s → 1.5s` 可以，`提升 200%` 不可以（除非原文就这么写）。
2. **百分比必须带范围或口径。** "开发效率提升约 25%" 比 "效率翻倍" 可信。
3. **不叠加两套量纲。** 同一句不要既给秒数又给百分比。
4. **一个项目里"带 `→` 的指标"不超过 2 个**，否则读者会开始怀疑。
5. 中文与数字之间留半角空格（`6 人团队`、`200+ 企业客户`），这是中文技术简历的通行排版。

## 四、禁止项清单

投递前逐条 grep，命中就删：

- 自我评价式形容词：`责任心强`、`抗压`、`积极主动`、`学习能力强`、`沟通良好`
- 无证据的熟练度：`精通`、`熟练掌握`、`了解`
- 简历内自陈：`期望薪资面议`、`可接受加班`、`求职意向：不限`
- 工具性内容：招聘平台（Boss / 猎聘等）的「个人优势」粘贴版、平台填写说明、投递备注
- 重复信息：概述里出现过的指标又在项目里写一遍；项目描述与工作经历重复
- 玩具项目铺开写：无真实用户的"商城/秒杀/博客"，最多 3 条且标"个人项目"
- 装饰性附录：技能雷达图、性格测评、证书墙（除非岗位硬要求）

## 五、诚实口径（这几处最容易翻车）

**Leader 年限**

不写"近 N 年任 Leader"，除非确实连续在职。正确写法：在概述里给累计值并交代现状。

```text
N 年前端，其中 M 年任前端团队 Leader（K 人团队）……现任 X 公司高级前端工程师。
```

累计口径 = 各段 Leader 时间段相加（例：2019.05–2020.10 + 2020.11–2024.10 ≈ 5 年 4 个月 → 写"5 年"）。两段之间有空档时按实际在职月份累加，不要取整成"近 5 年"。

**外包 / 驻场**

写成 `XX 科技（客户名）｜ 高级前端工程师（驻场交付）`：不隐瞒，也不把公司标签放大。是否保留括号由用户定。

**个人项目**

标注 `个人项目 · 全栈独立开发`，位置放最后，bullet 里写清"当前状态"（已上线 / 待切换 / 内测），不要伪装成商业项目。

**在职期间**

写"至今"，不要写死结束月份，避免每次更新简历都要改日期。

## 六、占位符规范

不确定的事实写成可见占位符，导出版里用 `.todo` 样式（灰字 + 左细线），并在交付消息末尾集中列出：

```text
量化指标待补：改造后单个页面平均开发工时变化 / 覆盖的页面占比 / 上线后缺陷率
```

占位符不超过 2 处。超过 2 处说明素材不够，应先回去问用户，而不是先出 PDF。
