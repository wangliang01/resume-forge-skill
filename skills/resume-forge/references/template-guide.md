# 模板使用指南

面向"我要把这份模板改成一封能投的简历"的场景，从上到下照着做即可。

> 路径说明：模板在 `assets/templates/<style>/index.html`，脚本在 `scripts/`，本文的相对路径都相对于 skill 目录（`~/.claude/skills/resume-forge` 或 `~/.agents/skills/resume-forge`）。给 agent 用的流程与硬指标写在 `SKILL.md`，本文是给人看的手册。

---

## 一、选哪个模板

| 你的情况 | 用这个 | 为什么 |
|---|---|---|
| 5~15 年经验，投中后台 / SaaS / 全栈 | **classic** | 单栏信息密度最高，深松石绿不刺眼，HR 打印出来也清楚 |
| 要黑白打印 / 投外企 / 团队偏设计 | **mono** | 无彩色，纯靠字重和细线分层，复印不糊 |
| 投大厂、管理岗，希望视觉更"重" | **navy** | 页眉色块给第一印象，双栏技能省版面 |
| 3~8 年，想一页投完 | **sidebar** | 副栏放联系方式/技能/教育，主栏全给项目 |

改风格比换模板省事：四份模板的 class 命名一致，`--accent` 一改就是另一套配色。

## 二、怎么改内容

### 2.1 只用改 `<body>`

```html
<div class="page">
  <header>…</header>          <!-- 姓名 / 岗位 / 联系方式 -->
  <section>…</section>        <!-- 每个 section 是一个区块 -->
</div>
```

`<style>` 里的东西默认不要动。复制一整段 `<section>` 来增删区块，比手写更安全。

### 2.2 class 速查

| class | 用途 | 注意 |
|---|---|---|
| `.sec-title h2` | 区块标题（个人概述 / 核心项目 …） | 标题右侧的细线是 CSS 画的，别自己加 `<hr>` |
| `.item` | 一个项目 = 标题行 + 项目描述 + bullet 列表 | 一个项目别超过 6 条 bullet |
| `.item-head` | 项目标题行 | 里面放 `.item-title` / `.badge` / `.when` |
| `.badge` | 角色标签（主导 / 前端 Leader / 个人项目） | 最多 1 个，标签太多等于没有标签 |
| `.desc` | 项目描述（一句话交代系统是什么、服务谁） | 必填，缺了 bullet 就悬空 |
| `ul.bullets > li` | 项目要点 | `<b>标签：</b>` + 动作 + 产物 + 结果 |
| `.k` | 关键数字高亮 | 一个项目里不超过 3 处 |
| `.job` | 工作经历一行 | 只写职责边界，别重复项目指标 |
| `.todo` | 待补占位符 | 导出前要么补数，要么删掉 |

### 2.3 加一个项目

```html
<article class="item">
  <div class="item-head">
    <span class="item-title">项目名称</span>
    <span class="badge">你的角色</span>
    <span class="when">2023.06 — 至今</span>
  </div>
  <p class="desc"><b>项目描述：</b>这个系统做什么、服务谁、当时要解决什么问题。</p>
  <ul class="bullets">
    <li><b>动作标签：</b>做了什么 → 交付了什么产物 → 带来什么可感知结果</li>
    <li><b>动作标签：</b>…</li>
  </ul>
</article>
```

## 三、内容怎么写

模板只解决"好看"，能不能约面取决于这几条。

### 3.1 bullet 三段式

```text
[2~4 字标签：] 做法 → 产物 → 服务对象/规模 → 结果
```

- ✅ `组件库：沉淀 20+ 业务组件，接入 8 条内部业务线，开发效率提升约 25%`
- ❌ `负责组件库建设，提升团队效率`（没有产物和结果）
- ❌ `精通 Vue3，熟悉 React`（自我声明，无证据）

### 3.2 数字规则

1. **有基线才写箭头**：`3.5s → 1.5s` 可以，凭空"提升 200%"不行。
2. **百分比带口径**："开发效率提升约 25%" 比 "效率翻倍" 可信。
3. **别改指标的含义**：原文是"开发效率提升 25%"，就别写成"重复页面开发量下降 25%"——换说法等于换事实。
4. 中文与数字间留半角空格：`6 人团队`、`200+ 企业客户`。

### 3.3 简历里不该出现的东西

投递前搜一遍，命中就删：

- 自我评价形容词：`责任心强`、`抗压`、`积极主动`、`学习能力强`
- 熟练度自评：`精通`、`熟练掌握`、`了解`
- 平台工具性内容：招聘平台的「个人优势」粘贴版、期望薪资面议、投递备注
- 重复信息：概述写过的指标又在项目里写一遍
- 玩具项目铺开写：没有真实用户的商城/秒杀/博客，最多 3 条且标注"个人项目"

### 3.4 头衔与年限要经得起追问

- **Leader 年限**按时间段累加，不要取整成"近 N 年"。累计 5 年 4 个月就写"5 年"，并在概述里交代当前岗位。
- **外包 / 驻场**写 `公司（客户）｜ 岗位（驻场交付）`：不隐瞒，也不放大，由你决定保留到什么程度。
- **在职**写"至今"，别写死结束月份。

## 四、调密度与页数

改模板顶部 `:root` 里的两个变量：

```css
--base-pt: 10pt;   /* 正文字号 */
--lh: 1.72;        /* 行高倍数 */
```

经验值（A4、双页、约 1.7 页内容量）：

| 字号 / 行高 | 结果 |
|---|---|
| 9.5pt / 1.68 | 两页，首页 ~95%，末页 ~70% —— 稳妥 |
| 10pt / 1.72 | 两页，首页 ~95%，末页 ~81% —— 更易读 |
| 10.5pt / 1.76 | 容易挤出第 3 页 |
| 9pt / 1.6 | 能塞进一页，但中文会糊 |

页数不对时按 [`layout-spec.md`](layout-spec.md) 的「分页失衡排查顺序」逐条试，**一次只改一个变量**，改完重新导出。

### 跨页开关

`.item` 上的 `break-inside` 是一个取舍：

- `auto`（默认）：页底不留白，但一个项目可能被拆到两页。
- `avoid`：项目整块不劈，但页底可能出现整块空白。

两页内容量在 1.5~1.9 页之间时，`auto` 通常更好看。想要"每个项目都完整显示"，就把双页模板改成 `avoid` 并接受留白，或干脆删到一个项目。

## 五、换配色

改 `:root` 里的 `--accent`（部分模板还有 `--accent-soft` / `--accent-dark`）：

| 色值 | 观感 | 适合 |
|---|---|---|
| `#14655f` 深松石 | 稳、不抢眼（classic 默认） | 通用技术岗 |
| `#1f3a5f` 藏青 | 商务、可信（navy/sidebar 默认） | 管理岗、大厂、传统行业 |
| `#2b2b2b` 近黑 | 极简（mono 默认） | 黑白打印、设计团队 |
| `#7a4b2a` 深棕 | 温和、少见 | 避免撞色时用 |
| `#3c4a5a` 石墨蓝 | 中性 | 不确定时的安全牌 |

规则：**主色只出现在时间、标签、关键数字和标题线上**，正文保持深灰。不要给正文上色，不要把两个主色混用。

## 六、打印设置

Chrome「打印」对话框中：

- **目标**：另存为 PDF
- **纸张**：A4
- **边距**：默认（模板用 `@page` 控制边距，选"无"会让内容贴边）
- **缩放**：100%（"适合页面"会重排，页数和断页都会变）
- **背景图形**：勾选（否则色块、左侧栏、标签底色全部消失）
- **页眉和页脚**：不勾选（否则每页印上 `file:///...` 和页码）

用 `scripts/export_pdf.sh` 导出则以上全部自动处理（macOS / Linux 同样适用，脚本自动找 Chrome）。

## 七、常见故障

| 现象 | 原因 | 解决 |
|---|---|---|
| `Failed to write file … 拒绝访问。(0x5)` | Chrome 不接受中文输出路径 | 先输出 `out.pdf` 再 `mv` 改名，或用 `scripts/export_pdf.sh` |
| 每页顶部出现 `file:///C:/...` | 没关页眉页脚 | 加 `--no-pdf-header-footer` |
| 色块 / 左侧色条打印不出来 | 没勾「背景图形」 | 勾选 `Background graphics` |
| 换了台电脑页数变了 | 中文字体 fallback 不同（微软雅黑 vs 苹方 vs 思源） | 全平台装 Noto Sans SC；模板字体栈已按 `Noto Sans SC → Microsoft YaHei → PingFang SC` 排好 |
| PDF 里文字选不中 / 模糊 | 用了截图或图片化导出 | 用 Chrome / `export_pdf.sh` 导出，模板本身是真文本 |
| 导出后第 2 页从半个项目开始 | 区块被劈开 | 见「跨页开关」 |
| 投递系统要求 PDF 小于 2MB | 嵌入字体较大 | Chrome 导出通常 ~1MB；超了用 `gswin64c -sDEVICE=pdfwrite -dPDFSETTINGS=/ebook` 压缩 |

## 八、版本管理建议

- 文件命名带版本：`我的简历-v1.0.html` / `我的简历-v1.0.pdf`，每次针对不同 JD 存一份，别覆盖。
- 只维护 `.html` 源文件，`.pdf` 是产物；改了文字就重新导出，不要手改 PDF。
- 投递记录另存一张表：公司 / 岗位 / JD 链接 / 投的哪一版 / 时间。
- 每版改动只动 1~2 处，出问题能立刻定位是哪次改坏的。

## 九、配合 AI 助手使用

装上本 skill 的 agent（Claude Code / Codex / Cursor / Pi / Freebuff 等）会按 `SKILL.md` 的流程自动走审计 → 重写 → 套模板 → 导出 → 验版。也可以手工把整份 HTML 交给任何 AI 改：

> 把这份简历的"核心项目"改成投 XX 岗位的版本，只改 bullet 文案，不许新增事实；数据缺失的地方用 `.todo` 占位符标出来。

要求它"只改文字、不动 CSS"、"不许编造指标"，产出质量会明显好于让它自由发挥。
